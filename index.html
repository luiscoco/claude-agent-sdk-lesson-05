MATCH CAPABILITY TO EFFECT

A tool contract and an approval strategy.

The live lab uses SDK-hosted policies from the installed 0.3.310 package. Local mode uses its own explicit router; an MCP transport is not the SDK permission engine.

Policy on the returned server config

const server = {
  ...createSdkMcpServer({
    name: 'workshop', tools: appTools,
  }),
  tools: [
    { name: 'save_review_note',
      permission_policy: 'always_ask' },
    { name: 'run_command',
      permission_policy: 'always_deny' },
  ],
};

// query({ prompt: messages, options: {
//   tools: [], mcpServers: { workshop: server },
//   permissionMode: 'default', canUseTool,
// } });

appTools contains positional tool(name, description, rawZodShape, handler, extras?) definitions. The full runnable implementation is in src/server/tools.ts.

What should the counters show?

Read-only: real handlers run; pre-approval can skip canUseTool.

Approved note: one host callback in live mode, one save handler, one in-memory change.

Declined or dontAsk: no save handler and no change. dontAsk opens no approval prompt.

Command denial: zero command handler calls. The stub also refuses execution if called directly.
